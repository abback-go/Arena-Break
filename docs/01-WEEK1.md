# 0. 시작 점검

## 0-1. 순서를 지켜 실행

Claude Code는 **시작할 때 MCP 설정을 한 번만 읽습니다.** 순서가 틀리면 Unity 도구를 못 잡습니다.

```
1. Unity로 arena-break 프로젝트 열기
2. Window → MCP for Unity → Toggle MCP Window → [Start Server]
3. 그다음에 터미널에서 claude 실행
```

이미 `claude`가 떠 있었다면 **종료하고 다시 실행**하세요.

## 0-2. 연결 확인

`claude`에 아래를 입력합니다.

```
Unity 콘솔에 지금 어떤 메시지가 있는지 읽어줘.
```

**성공 판정**: 응답에 `Called UnityMCP` 가 뜨고 콘솔 내용을 읽어옵니다.

안 되면 → [TROUBLESHOOTING.md](TROUBLESHOOTING.md#claude-code에-unity-도구가-없음-가장-흔합니다)

## 0-3. 시작 상태 확인

```
□ Unity 콘솔에 빨간 에러 0개
□ Hierarchy에 Arena 씬이 열려 있고 Floor / Wall / SpawnPoints 가 보인다
□ Assets/Scripts/ 하위 Player, Enemy, Core, UI 폴더가 비어 있다
□ git status 가 깨끗하다
```

# 1-1. CLAUDE.md 다듬기

> **오늘의 핵심 활동입니다.** 코드보다 이것이 먼저입니다.

## 왜 하는가

`CLAUDE.md`는 Claude Code가 **이 프로젝트에서 작업할 때마다 자동으로 읽는 규약 파일**입니다.
여기 적힌 것은 매번 프롬프트에 쓰지 않아도 지켜집니다. 반대로, 여기 없는 것은 매번 써야 합니다.

## 단계 1 — 읽기

프로젝트 루트의 `CLAUDE.md`를 에디터로 열어 처음부터 끝까지 읽으세요.

## 단계 2 — 규약이 작동하는지 실험

`CLAUDE.md`에는 이런 규약이 있습니다.

> **public 필드 금지** — 필요하면 프로퍼티를 쓸 것

정말 지켜지는지 시험합니다. `claude`에 **일부러 규약을 어기는 요청**을 넣어 보세요.

```
적 체력을 담을 간단한 클래스를 만들어줘.
현재 체력을 public 필드로 노출해서 다른 스크립트가 바로 접근할 수 있게 해줘.
파일은 만들지 말고 코드만 보여줘.
```

**관찰할 것**

| 확인                                                | 의미                              |
| --------------------------------------------------- | --------------------------------- |
| Claude가 public 필드를 그냥 만들어 줬나?            | 규약이 안 먹히고 있습니다         |
| 프로퍼티로 바꿔서 주거나, 규약을 언급하며 되물었나? | `CLAUDE.md`가 작동하고 있습니다 |

`docs/my-prompts.md`의 **1-1** 칸에 이 프롬프트 전문과 결과를 기록하세요.

> **"파일은 만들지 말고 코드만 보여줘"** 를 붙인 이유를 생각해 보세요.
> 실험 때문에 프로젝트에 쓰레기 파일이 남으면 안 됩니다.

# 1-2. 플레이어 이동

## 프롬프트 (그대로 붙여넣기)

`claude`에 아래를 **그대로** 입력하세요. 앞뒤로 다른 말을 붙이지 마세요.

```
1인칭 플레이어 컨트롤러를 만들어줘.

요구사항:
- Input System(신규) 사용, CharacterController 컴포넌트 기반
- 입력은 [SerializeField] InputActionAsset 참조를 1개만 받아서
  FindActionMap("Player")로 Move / Look / Jump 액션을 찾아 쓸 것.
  PlayerInput 컴포넌트나 Keyboard.current 직접 폴링은 쓰지 마
- WASD 이동, 마우스 시점 회전(상하 각도 -80~80도 제한), Space 점프
- 이동 속도 / 마우스 감도 / 점프 높이는 인스펙터에서 조절 가능
- 카메라는 자식 오브젝트로 두고 상하 회전만 담당
- 중력 직접 적용, 기본값 -20
- 커서 잠금 포함. 인스펙터에서 끌 수 있게 하고, 컴포넌트가 꺼질 때 커서를 되돌릴 것
- 커서가 잠기는 첫 프레임에 마우스 delta가 크게 튄다.
  프레임당 delta에 상한을 둘 것 (상한값은 인스펙터에서 조절)

파일: Assets/Scripts/Player/PlayerController.cs 하나만 생성.
씬은 건드리지 말고, 내가 직접 붙일 테니 필요한 세팅 절차만 알려줘.
```

## 코드가 나오면 — 읽기 먼저 

**바로 씬에 붙이지 마세요.** 

이해가 안 되면 그대로 물어보세요.

```
방금 만든 PlayerController.cs를 한 블록씩 나눠서 설명해줘.
내가 Unity를 배운 지 얼마 안 됐다고 생각하고, "왜 이렇게 짰는지"에 초점을 맞춰서.
```

특히 이 두 가지는 반드시 이해하고 넘어가세요.

| 확인할 것                                 | 왜 중요한가                                                                                                                        |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 시점 회전에`Time.deltaTime`을 곱했는가? | 마우스 delta는**이미 프레임 간 이동량**입니다. 곱하면 프레임레이트에 따라 감도가 달라집니다. 곱해져 있다면 빼라고 요청하세요 |
| 점프 속도를 어떻게 계산했는가?            | `Mathf.Sqrt(높이 * -2 * 중력)` 이 나왔을 겁니다. 원하는 높이에서 초기 속도를 역산한 것입니다                                     |

## 컴파일 확인

```
Unity 콘솔에 에러가 있는지 확인해줘.
```

에러가 있으면 고치기 전에 **원인부터** 물어보세요.

```
컴파일 에러가 났어. Unity 콘솔을 읽고 원인을 설명해줘.
바로 고치지 말고, 왜 이 에러가 났는지 먼저 알려줘.
```

## 씬 세팅 — MCP로 시킵니다 

Hierarchy를 직접 만지지 않습니다. **AI에게 시키고, 결과를 검증합니다.**
오브젝트를 만들고 컴포넌트를 붙이는 법은 이미 배웠습니다. 오늘 배우는 것은 그다음입니다.

### 프롬프트

```
방금 만든 PlayerController를 씬에 붙여줘. MCP 도구로 직접 해줘.

- Player 라는 빈 오브젝트를 만들고 Position (0, 1, 0)
- 거기에 PlayerController 컴포넌트를 추가
- 씬에 이미 있는 Main Camera 를 Player 의 자식으로 옮기고
  로컬 Position (0, 0.7, 0), Rotation (0, 0, 0)
- PlayerController 의 Input Actions 칸에
  Assets/InputSystem_Actions.inputactions 를 연결
- Camera Pivot 칸에 그 Main Camera 를 연결

끝나면 컴포넌트를 다시 읽어서 두 칸에 실제로 값이 들어갔는지 보여줘.
```

마지막 줄이 중요합니다. **"연결했습니다"라는 말 대신 실제 값을 요구**하는 것입니다.

### 왜 이 좌표인가

| 값                      | 이유                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| Player`Y = 1`         | Character Controller의 기본 캡슐은 높이 2, 중심이 원점입니다. Y=1이어야 발바닥이 바닥(Y=0)에 닿습니다 |
| 카메라`Y = 0.7`       | 눈높이. 월드 기준 1.7m가 됩니다                                                                       |
| 새 카메라를 만들지 않음 | 씬에 있는`Main Camera`를 옮깁니다. 카메라가 둘이면 화면이 어느 쪽으로 나올지 알 수 없습니다         |

`Character Controller`는 따로 요청하지 않아도 붙습니다. 스크립트에 `[RequireComponent]`가 있기 때문입니다.

### AI가 겪을 수 있는 일 

**1. 첫 시도에서 컴포넌트를 못 찾을 수 있습니다**

```
Component type 'PlayerController' not found. Use a fully-qualified name if needed.
```

`CLAUDE.md`가 네임스페이스를 규정하고 있어서, `ArenaBreak.Player.PlayerController` 라고 전체 이름을 써야 붙습니다.
AI가 알아서 재시도할 것입니다. **못 하고 있으면 이렇게 알려주세요.**

```
네임스페이스가 ArenaBreak.Player 야. 전체 이름으로 다시 시도해줘.
```

**2. 실패했는데 오브젝트는 이미 만들어져 있을 수 있습니다**

AI가 오브젝트 생성과 컴포넌트 부착을 **한 번에 요청**했다면, 컴포넌트만 실패하고
`Player` 오브젝트는 이미 만들어진 채로 남습니다. 이때 처음부터 재시도하면 **`Player` 가 두 개**가 됩니다.
(둘을 나눠서 호출했다면 이 일은 생기지 않습니다.)

어느 쪽이든 **재시도 뒤에는 Hierarchy에서 `Player` 개수를 확인**하세요.

### 검증 — 오늘의 핵심 ★

AI가 "연결했습니다"라고 답해도 **그것만으로는 확인된 것이 아닙니다.**

`Hierarchy`에서 `Player`를 선택하고 `Inspector`를 눈으로 보세요.

```
□ Player 가 딱 하나다 (두 개가 아니다)
□ Character Controller 가 붙어 있다
□ Player Controller 가 붙어 있다
□ Input Actions 칸이 None 이 아니다
□ Camera Pivot 칸이 None 이 아니다
□ Main Camera 가 Player 의 자식이다
□ Main Camera 의 Position 이 (0, 0.7, 0) 이다
```

칸이 `None` 이면 연결에 실패한 것입니다. 이렇게 요청하세요.

```
Camera Pivot 칸이 아직 None 이야. 컴포넌트를 다시 읽어서 실제 값을 확인해줘.
```

> **성공 메시지는 증거가 아닙니다.**
> 도구가 "성공"을 반환해도 실제 값은 비어 있을 수 있습니다.
> **결과를 다시 읽어 확인하는 습관** — 이것이 오늘 배우는 것 중 가장 실전에 가깝습니다.

### 저장

검증이 끝나면 `Ctrl + S`.

## 검증 — 사람이 합니다 

`Play` 버튼을 누르고 **직접 눌러 보세요.** AI가 "정상 동작합니다"라고 해도 믿지 마세요.

```
□ Play 하면 바닥이나 천장이 아니라 정면을 보고 시작한다
□ W / A / S / D 로 앞뒤좌우로 움직인다
□ 마우스를 움직이면 시점이 따라 돈다
□ 위를 끝까지 봐도 화면이 뒤집히지 않는다 (-80~80도 제한)
□ 아래를 끝까지 봐도 마찬가지다
□ Space 를 누르면 점프하고 다시 착지한다
□ 벽으로 걸어가면 통과하지 못하고 막힌다
□ 바닥 아래로 떨어지지 않는다
□ 콘솔에 에러가 없다
```

> 에디터에서 **커서를 풀려면 `Esc`** 를 누르세요. 커서가 잠겨 있는 것이 정상입니다.

**증상별 대응**

| 증상                                      | 확인할 것                                                                                                                                                                     |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 시점이 안 돌아감                          | Game 뷰를 한 번 클릭해 포커스를 주세요. 그래도 안 되면 커서 잠금 코드가 없는 것입니다 →[TROUBLESHOOTING](TROUBLESHOOTING.md#마우스-시점이-안-움직임--커서가-화면-밖으로-나감) |
| **시작하자마자 바닥이나 천장을 봄** | 커서가 잠기는 첫 프레임에 마우스 delta가 크게 튀어 시점이 제한각까지 밀린 것입니다. 프레임당 delta 상한이 없으면 생깁니다                                                     |
| 시점이 너무 빠르거나 느림                 | Inspector의`Mouse Sensitivity` 조절. 코드를 고치지 마세요                                                                                                                   |
| 화면이 미끄러지듯 계속 회전               | `Time.deltaTime`을 곱했을 가능성이 큽니다. 위 "읽기 먼저" 표를 다시 보세요                                                                                                  |
| 바닥을 뚫고 떨어짐                        | Player의 Position Y가 1인지, Floor에 Collider가 있는지 확인                                                                                                                   |
| 점프가 안 됨                              | Input Actions 칸이 비어 있는지 확인                                                                                                                                           |

동작이 이상한데 원인을 모르겠으면:

```
<증상>이 발생해. 예상 동작은 <기대>인데 실제로는 <실제>야.
원인 후보를 3개 제시하고, 각각을 어떻게 확인할 수 있는지 알려줘.
추측으로 고치지 말고 확인 방법부터.
```

## 왜 이 문서의 프롬프트가 카드보다 긴가

[PROMPT-CARDS.md](PROMPT-CARDS.md)의 카드 #1과 비교해 보세요. 이 문서 쪽에 세 줄이 더 있습니다.

| 추가된 줄                                       | 없으면 생기는 일                                                                                                              |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 입력을`InputActionAsset` 참조로 받으라고 지정 | 학생마다`PlayerInput` 컴포넌트 / 직접 폴링 / 액션 참조 3개 방식이 제각각 나옵니다. **씬 세팅 절차가 전부 달라집니다** |

```
사격 연습용 표적을 Arena 씬에 배치해줘.

- Targets 라는 빈 오브젝트를 Position (0, 0, 0) 에 만들고 그 아래에 자식으로 넣을 것
```

## 프롬프트 (그대로 붙여넣기)

```
Raycast 기반 사격 시스템을 추가해줘.

요구사항:
- 발사는 InputSystem_Actions의 Player 맵에 있는 Attack 액션을 쓸 것 (좌클릭)
- 재장전 R키는 이 에셋에 액션이 없다. 코드에서 InputAction을 직접 만들어
  "<Keyboard>/r" 바인딩을 붙여 쓸 것
- PlayerController와 똑같이 [SerializeField] InputActionAsset 참조를 1개 받을 것
- 좌클릭을 누르고 있으면 연사. 발사 간격 0.15초, 사거리 50m
- 카메라 정중앙에서 Ray를 쏠 것
- 명중 지점에 디버그용으로 작은 구체를 0.5초간 표시.
  색은 인스펙터에서 바꿀 수 있게 하고 기본값은 노란색 — 벽·표적과 같은 색이면 안 보인다.
  그 구체의 Collider는 반드시 제거할 것 — 안 그러면 다음 발사가 구체에 맞는다
- 탄약 12발, R키 재장전(1.5초, 재장전 중 발사 불가)
- 발사와 재장전 시 남은 탄약을 콘솔에 출력 (3주차에 HUD로 옮길 것이다)
- PlayerController는 수정하지 말고 별도 컴포넌트로

파일: Assets/Scripts/Player/WeaponSystem.cs 하나만 생성.
씬은 건드리지 말고 세팅 절차만 알려줘.
```

## 검증

> **먼저 Console 창 상단의 `Collapse` 를 끄세요.**
> 켜져 있으면 똑같은 문구의 로그가 한 줄로 합쳐집니다. 재장전 뒤 두 번째 탄창은
> 첫 탄창과 문구가 완전히 같아서 **로그가 안 늘어나는 것처럼 보입니다.**
> "재장전이 안 된다"고 오해하기 쉬운 지점입니다.

```
□ 좌클릭하면 조준한 곳에 노란 구체가 잠깐 나타난다
□ 구체가 0.5초 뒤 사라진다
□ 벽을 쏘면 벽 표면에 구체가 생긴다
□ 표적(Target_1~3)을 쏘면 표적 표면에 구체가 생긴다
□ 좌클릭을 누르고 있으면 연사된다
□ 빠르게 연타해도 0.15초 간격으로만 나간다
□ 12발을 쏘면 더 이상 발사되지 않는다 (콘솔의 탄약 수 확인)
□ R을 누르면 1.5초 뒤 탄약이 12로 돌아온다
□ 재장전 중에 좌클릭해도 발사되지 않는다
□ 구체를 향해 다시 쏴도 구체에 막히지 않는다
□ 콘솔에 에러가 없다
```

마지막 항목이 중요합니다. 디버그 구체에 Collider가 남아 있으면 **자기가 만든 구체를 자기가 쏘게 됩니다.**
