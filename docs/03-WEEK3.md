# 3-1. 게임 상태 머신

## 먼저 — 플레이어에게 체력을 붙입니다

2장에 만든 `Health` 를 그대로 씁니다. **새로 만들지 않습니다.**

```
씬의 Player 에 ArenaBreak.Core.Health 컴포넌트를 붙여줘.
최대 체력은 500.

끝나면 컴포넌트를 다시 읽어서 값이 들어갔는지 보여줘.
```

### 왜 500인가

적의 공격 데미지가 **10** 입니다. 체력이 `Health` 의 기본값 100이면 **10대 맞고 죽습니다.**
버티는 시간이 너무 짧아서 웨이브가 넘어가는 것을 볼 새도 없이 게임오버가 뜹니다.

```
500 ÷ 10 = 50대
```

50대면 5웨이브를 끝까지 볼 만합니다. **숫자를 바꿀 때는 근거가 되는 다른 숫자를 같이 보세요.**
공격 데미지를 바꾸면 이 값도 다시 계산해야 합니다.

체력바 크기는 그대로 둡니다. 비율로 줄어들기 때문에 최대 체력이 얼마든 화면은 똑같이 보입니다.

`Play` 를 눌러 적에게 맞아 보세요. `Player` 를 선택해두면 `Current Health` 가 줄어드는 것이 보입니다.

> **이것이 2장 2-1에서 인터페이스를 나눈 이유입니다.**
> 플레이어용 체력 코드를 한 줄도 새로 쓰지 않았습니다.
> `WeaponSystem` 도 `EnemyAI` 도 고치지 않았습니다.

## 프롬프트 (그대로 붙여넣기)

```
게임 상태 머신을 만들어줘.

- 상태: Ready / Playing / GameOver / Cleared — enum + switch로 단순하게
- Ready에서 시작해 잠깐 뒤 Playing으로 (대기 시간은 인스펙터에서 조절)
- 플레이어 Health의 사망 event를 구독해서 GameOver로
- WaveSpawner의 전체 클리어 event를 구독해서 Cleared로
- GameOver / Cleared 에서: 커서 표시, Time.timeScale = 0
- 그 상태에서 R키를 누르면 현재 씬을 다시 로드
  (Time.timeScale을 1로 되돌리는 것을 잊지 말 것)
- 상태가 바뀌면 C# event로 알릴 것 — HUD가 구독할 것이다
- 구독한 event는 OnDisable에서 반드시 해제할 것
- GameOver / Cleared 로 갈 때 플레이어 조작을 멈출 것.
  timeScale = 0 은 Update를 멈추지 않아서, 안 끄면 죽은 뒤에도 총이 나간다
  PlayerController 와 WeaponSystem 을 각각 [SerializeField] 로 받아 enabled 를 끌 것.
  배열이나 리스트 하나로 묶지 마 — 타입이 넓어지면 인스펙터에서 엉뚱한 것도 들어간다
- Esc로 게임을 종료할 것 (Application.Quit). 어느 상태에서든 눌리게
- R키와 Esc는 InputSystem_Actions 에셋에 액션이 없다.
  WeaponSystem의 재장전처럼 코드에서 InputAction을 만들어 쓸 것

파일: Assets/Scripts/Core/GameManager.cs 하나만 생성.
WaveSpawner와 PlayerController는 수정하지 마.
씬은 건드리지 말고 세팅 절차만 알려줘.
```

### 여기서 지정한 것들

| 지정한 줄                           | 없으면 생기는 일                                                                   |
| ----------------------------------- | ---------------------------------------------------------------------------------- |
| "R키는 액션이 없다"                 | 1장 재장전 때와 같은 함정입니다.**한 번 겪은 함정은 프롬프트에 미리 씁니다** |
| "timeScale을 1로 되돌릴 것"         | 재시작했는데 화면이 멈춰 있습니다. 가장 흔한 버그입니다                            |
| **"플레이어 조작을 멈출 것"** | 이게 없으면**죽은 뒤에 총알이 한 발 더 나갑니다.** 아래에 이유를 적었습니다  |
| **"Esc로 종료"**              | 커서가 잠긴 채로는 창의 X 를 누르기 어렵습니다. Esc 로 커서를 풀고 닫습니다. 3-5에서 확인합니다 |
| "상태가 바뀌면 event로 알릴 것"     | HUD가`Update()`에서 상태를 폴링하게 됩니다                                       |
| "WaveSpawner는 수정하지 마"         | 2장에 완성한 것을 건드리지 않게 막습니다                                           |

### timeScale = 0 의 함정 ★★

`Time.timeScale = 0` 이 멈추는 것과 멈추지 않는 것을 구분해야 합니다.

| 멈춘다                            | 멈추지 않는다                                     |
| --------------------------------- | ------------------------------------------------- |
| `Time.deltaTime`, `Time.time` | **`Update()` 호출 자체**                  |
| `WaitForSeconds`                | `WaitForSecondsRealtime`, `Time.unscaledTime` |
| 물리 시뮬레이션                   | **입력(Input System)**                      |

여기서 두 가지가 나옵니다.

**1. 대기를 코루틴 + `WaitForSeconds` 로 만들면 영원히 안 돌아옵니다.**
정지 상태에서 시간이 흐르지 않기 때문입니다. `Time.unscaledTime` 이나 `WaitForSecondsRealtime` 을 써야 합니다.

**2. 정지시켰다고 플레이어가 멈추지 않습니다.** ★

`Update()` 는 계속 돌고 입력도 살아 있습니다. 실제로 이런 일이 생깁니다.

```
죽는다 → timeScale = 0 → 화면은 멈춤 → 좌클릭하면 총알이 한 발 나감
```

`Time.time` 이 얼어붙은 순간 `Time.time >= 다음발사시각` 이 한 번 참이 되기 때문입니다.
그래서 **정지시킬 때 플레이어 조작 컴포넌트를 꺼야 합니다.**

> 끄면 각 컴포넌트의 `OnDisable` 이 입력 액션까지 함께 해제해 줍니다.
> **"멈춘 것처럼 보인다"와 "멈췄다"는 다릅니다.**

```
방금 만든 GameManager.cs에서 재시작 처리 부분을 설명해줘.
Time.timeScale을 언제 0으로 만들고 언제 1로 되돌리는지,
그 순서가 왜 그래야 하는지 중심으로.
```

## 씬 세팅

```
GameManager 컴포넌트를 씬의 GameManager 오브젝트에 붙여줘.
(2장에 WaveSpawner를 붙인 그 오브젝트다)

- 플레이어 Health 참조 칸에 씬의 Player 를 연결
- WaveSpawner 참조 칸에 같은 오브젝트의 WaveSpawner 를 연결
- PlayerController 칸과 WeaponSystem 칸에도 씬의 Player 를 연결

끝나면 컴포넌트를 다시 읽어서 네 칸에 실제로 값이 들어갔는지 보여줘.
None 인 칸이 하나라도 있으면 알려줘.
```

### 여기서 빠뜨리면 생기는 일 ★

`GameManager` 는 참조를 **네 개** 받습니다. 앞의 두 개(`Health`, `WaveSpawner`)는 상태를 읽는 용도이고,
뒤의 두 개(`PlayerController`, `WeaponSystem`)는 **정지시킬 때 끄는 용도**입니다.

뒤의 두 칸이 `None` 이면 이렇게 됩니다.

```
죽는다 → timeScale = 0 → 화면은 멈춤
  → 좌클릭하면 총알이 한 발 나감
  → 마우스를 움직이면 시점이 계속 돈다
```

**컴파일 에러도, 콘솔 에러도 나지 않습니다.** 코드는 완벽하고 칸 하나가 비었을 뿐입니다.

> 총알이 **딱 한 발만** 나가는 것이 단서입니다. `timeScale = 0` 이면 `Time.time` 이 멈춰서
> 다음 발사 시각 비교가 영원히 거짓이 됩니다. 그래서 두 번째 발은 안 나갑니다.

Inspector에서 `GameManager` 를 선택해 **네 칸을 눈으로** 확인하세요.

```
Player Health      → Player
Wave Spawner       → GameManager
Player Controller  → Player
Weapon System      → Player
```

### 칸 대신 배열이 나왔다면 ★

AI가 두 칸으로 나누지 않고 `Player Controls` 같은 **배열 하나**로 만들 수 있습니다.
프롬프트에 형태를 못박아도 가끔 이렇게 나옵니다.

배열이면 원소 타입이 보통 `Behaviour` 인데, 이러면 인스펙터의 선택 창이
컴포넌트가 아니라 **게임오브젝트 목록**을 보여줍니다.

```
Select Behaviour
  None
  Camera
  Directional Light
  Floor          ← 조작 컴포넌트가 아닌 것까지 다 나온다
  GameManager
  Player
```

여기서 `Player` 를 골라도 **그 안의 어느 컴포넌트가 들어갈지 알 수 없습니다.**
`Floor` 를 넣어도 컴파일되고 에러도 안 납니다. 그냥 안 꺼질 뿐입니다.

고쳐 달라고 하세요.

```
GameManager 의 플레이어 조작 컴포넌트 배열을 없애고,
PlayerController 와 WeaponSystem 을 각각 [SerializeField] 로 받는 칸 두 개로 바꿔줘.
게임이 끝날 때 그 둘의 enabled 를 false 로, 재시작할 때 true 로 되돌릴 것.
다른 동작은 그대로 유지해줘.
```

바꾸면 각 칸이 **그 타입만** 받습니다. `Player` 오브젝트를 드래그하면 Unity가 맞는 컴포넌트를 골라 넣고,
엉뚱한 것은 애초에 들어가지 않습니다.

> **타입을 좁히면 인스펙터가 검증을 대신해 줍니다.**
> 오늘의 주제(에러 없이 조용히 틀리는 것)를 막는 가장 값싼 방법입니다.

# 3-2. HUD

## 먼저 알아야 할 것 — 지금 값이 어디 있나

| 보여줄 것       | 지금 어디에 있나         | 알림 방법이 있나                 |
| --------------- | ------------------------ | -------------------------------- |
| 체력            | `Player` 의 `Health` | ✅`HealthChanged` event        |
| 웨이브 번호     | `WaveSpawner`          | ✅`WaveStarted` event          |
| 게임 상태       | `GameManager`          | ✅ 3-1에서 만든 event            |
| **탄약**  | `WeaponSystem`         | ❌**`Debug.Log` 뿐이다** |
| **킬 수** | 아무도 안 센다           | ❌**없다**                 |

아래 둘은 **없는 것을 먼저 만들어야** 합니다. HUD부터 만들면 붙일 곳이 없습니다.

## 없는 것 두 개 먼저 (프롬프트)

```
HUD가 구독할 수 있도록 두 곳에 event를 추가해줘.

- WeaponSystem: 탄약이 변할 때 (현재, 최대) 를 알리는 event.
  기존 Debug.Log는 지울 것 — 이제 화면에 나온다
- WaveSpawner: 적이 죽을 때마다 누적 킬 수를 알리는 event.
  이미 각 적의 사망 event를 구독하고 있으니 거기서 세면 된다

기존 기능과 공개 event 시그니처는 그대로 유지할 것.
파일 2개만 수정하고 다른 파일은 건드리지 마.
```

수정 후 **직접 확인합니다.**

```bash
git diff Assets/Scripts/Player/WeaponSystem.cs Assets/Scripts/Core/WaveSpawner.cs
```

```
□ 기존 event 3개(WaveStarted / WaveCleared / AllWavesCleared)의 이름과 타입이 그대로인가?
□ 탄약·재장전·풀링 로직이 그대로인가?
□ 요청하지 않은 파일이 바뀌지 않았나?
```

## HUD 만들기 (프롬프트)

```
HUD를 만들어줘. UI Toolkit 말고 uGUI로.
텍스트는 TextMeshPro 말고 레거시 UnityEngine.UI.Text 를 쓸 것.
(TMP를 처음 쓰면 임포트 창이 떠서 그동안 MCP가 멈춘다)

표시할 것:
- 좌하단: 체력바. 어두운 배경 Image 안에 빨간 Image를 넣고,
  그 빨간 Image의 RectTransform 앵커 폭으로 줄일 것.
  Image.fillAmount는 쓰지 마 — 이유는 아래에 적었다.
  Health의 HealthChanged event 구독
- 우하단: 탄약 "현재 / 최대". WeaponSystem의 탄약 event 구독
- 상단 중앙: 웨이브 번호. WaveSpawner의 WaveStarted event 구독
- 상단 우측: 킬 수. WaveSpawner의 킬 event 구독
- 화면 중앙: GameOver / Cleared 안내 문구와 "R키로 재시작".
  평소에는 숨기고 GameManager의 상태 event로 켤 것

- Update()에서 폴링하지 말 것. 전부 event 구독으로
- 구독은 OnEnable, 해제는 OnDisable
- 참조는 전부 [SerializeField] 로 받을 것. Find 계열 금지

파일: Assets/Scripts/UI/HUDController.cs 하나만 생성.
UI 오브젝트는 아직 만들지 말고, 어떤 오브젝트가 필요한지 목록만 알려줘.
```

### "UI Toolkit 말고 uGUI로" 를 쓰는 이유

둘 다 Unity의 정식 UI 시스템입니다. 그냥 두면 AI가 하나를 골라줍니다.
**기술 선택은 사람이 합니다.** 이 수업은 인스펙터에서 눈으로 확인하는 흐름이라 uGUI가 맞습니다.

> MCP의 `manage_ui` 도구는 **UI Toolkit 전용**입니다. uGUI 전용 도구는 없어서
> Canvas와 위젯을 오브젝트·컴포넌트 단위로 하나씩 만들게 됩니다. 그 과정의 함정은 아래에 정리했습니다.

**"uGUI로" 만으로는 부족합니다.** TextMeshPro도 uGUI입니다.
`TextMeshProUGUI` 는 Canvas 위에서 도는 uGUI 컴포넌트라, 이 말로는 하나도 걸러지지 않습니다.
그래서 프롬프트에 **레거시 `UnityEngine.UI.Text`** 라고 따로 못박았습니다.

Unity 6에서는 `GameObject → UI → Text` 가 **기본으로 TextMeshPro** 입니다.
레거시는 `UI → Legacy → Text` 로 한 단계 더 들어가야 합니다. 아무 말 없으면 TMP가 나옵니다.

## UI 오브젝트 배치

AI가 알려준 목록대로 MCP에 시킵니다.

```
방금 알려준 UI 오브젝트들을 씬에 만들고 HUDController 에 연결해줘. MCP 도구로 직접 해줘.

끝나면 HUDController 의 각 참조 칸에 실제로 값이 들어갔는지 다시 읽어서 보여줘.
```

### UI 오브젝트가 잘 안 만들어지면

MCP로 UI 생성이 잘 안 되면 **손으로 만들어도 됩니다.** 오늘의 목표는 UI 배치 기술이 아닙니다.

```
GameObject > UI > Canvas
GameObject > UI > Legacy > Text     ← Legacy 를 반드시 거칠 것
```

> `GameObject > UI > Text` 는 Unity 6에서 **TextMeshPro** 입니다. 한 단계 더 들어가야 레거시입니다.

### uGUI를 만들 때 밟는 함정 4개 ★★

**실제로 다 밟고 적은 것**입니다. HUD가 안 보이면 여기부터 보세요.

| # | 증상                                          | 원인                                                                                                     | 대응                                                         |
| - | --------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 1 | HUD가**아예 안 보임**                   | 컴포넌트로 추가한`Canvas` 는 **World Space가 기본**이다. 메뉴로 만들면 Overlay                   | `Render Mode` 를 `Screen Space - Overlay` 로             |
| 2 | 체력바가**줄지 않고 항상 꽉 참**        | `Image.fillAmount` 는 **Source Image(스프라이트)가 있어야** 동작한다. 코드로 만든 Image에는 없다 | 스프라이트를 넣거나,`RectTransform` 앵커 폭으로 줄인다     |
| 3 | HUD가**가장자리만 잘려 안 보임**        | Game 뷰 해상도가 창보다 크고`Scale` 이 높으면 중앙만 보인다. HUD는 전부 가장자리에 있다                | 해상도를`Free Aspect` 로, 또는 `Scale` 을 왼쪽 끝으로    |
| 4 | 값 수정이 거부됨                              | `This cannot be used during play mode`                                                                 | **Play를 먼저 멈춘다**                                 |

1번과 2번은 **에러가 하나도 안 납니다.** 콘솔은 깨끗한데 화면만 비어 있습니다.

> **이것이 3장의 주제입니다.**
> 에러가 없다는 것은 코드가 맞다는 뜻이 아닙니다. **눈으로 본 것만 검증된 것입니다.**

### 폰트 — TextMeshPro를 쓰지 않는 이유 ★

**한글이 안 나옵니다.** 이게 첫 번째 이유입니다.

TMP는 **미리 구운 아틀라스에 있는 글자만** 그립니다. 기본 폰트(`LiberationSans SDF`)에는
라틴 문자밖에 없어서 한글은 전부 □ 로 떨어집니다.

```

R□□ □□□          ← "R키로 재시작" 이 이렇게 보인다
```

영문은 멀쩡히 나오고 한글만 깨져서, **폰트 문제라는 것을 알아채기까지 시간이 걸립니다.**

레거시 `UnityEngine.UI.Text` 는 기본 폰트가 시스템 폰트라 한글이 그냥 나옵니다.
그래서 이 프로젝트는 **레거시 `UnityEngine.UI.Text`** 를 씁니다.

부수적으로, TMP를 처음 쓰면 "TMP Essentials를 임포트하겠느냐"는 창이 뜨고
**그 창이 떠 있는 동안 MCP가 멈춥니다.**

**"uGUI로" 라고만 쓰면 안 막힙니다.** TextMeshPro도 uGUI라서 그 말로는 걸러지지 않습니다.
프롬프트에 **레거시 `UnityEngine.UI.Text`** 라고 못박아야 합니다.

### 이미 TMP로 만들어졌다면

되돌리지 않아도 됩니다. 두 가지만 처리하면 그대로 진행할 수 있습니다.

**1. 임포트 창이 떠 있다면 `Import TMP Essentials` 를 누릅니다**

- `Import TMP Essentials` — 누릅니다
- `Import TMP Examples & Extras` — 안 눌러도 됩니다

창이 닫히면 `Assets/TextMesh Pro/` 폴더가 생깁니다. 그대로 두면 됩니다.
**창이 떠 있는 동안 보낸 MCP 요청은 멈춰 있었으니, 닫은 뒤 다시 시도하세요.**

**2. 한글이 □ 로 보이면 화면 문구를 영문으로 바꿉니다**

가장 싼 해결입니다. 문구가 `[SerializeField]` 로 나와 있으면 **코드를 안 고쳐도 됩니다.**

```

  GAME OVER
  Press R to Restart · Esc to Quit
```

**Play를 멈춘 상태에서** 고치고 `Ctrl + S`. Play 중에 고친 값은 저장되지 않습니다.

HUD의 나머지(`WAVE 1 / 5`, `KILLS 0`, `6 / 12`)는 이미 영문·숫자라 문제없습니다.

> 한글을 꼭 쓰겠다면 `Window → TextMeshPro → Font Asset Creator` 로 한글 폰트 에셋을
> 직접 만들어야 합니다. `Character Set` 을 `Unicode Range (Hex)` 로 놓고 `AC00-D7A3`
> (완성형 11,172자), `Atlas Resolution` 을 4096×4096으로 잡습니다.
> 만든 뒤 TMP 텍스트마다 `Font Asset` 을 교체해야 합니다. **수업 중에 할 작업은 아닙니다.**

# 3-4. AI 코드 리뷰 ★

> **이 수업 3주의 클라이맥스입니다.** 

## 왜 하는가

지금까지 AI가 쓴 코드를 여러분이 검증했습니다.
이번에는 **AI에게 검증을 시키고, 그 검증 결과를 여러분이 다시 검증합니다.**

## 프롬프트 (그대로 붙여넣기)

```
지금까지 작성된 Assets/Scripts 전체를 리뷰해줘.

다음 관점으로 문제를 찾아 심각도 순으로 정리:
- Update()에서의 불필요한 연산 / GetComponent 호출
- null 참조 가능 지점
- event 구독 후 해제 누락 (메모리 누수)
- 책임이 뒤섞인 클래스
- CLAUDE.md 규약 위반

각 항목마다 파일:줄 번호와 수정 방향을 제시하되, 아직 고치지는 마.
```

마지막 줄이 중요합니다. **고치기 전에 판단할 시간을 확보합니다.**

## 진행 방법 

### 1단계. 지적을 하나씩 열어 확인한다 

리뷰 결과를 그대로 믿지 마세요. **파일을 직접 열어 그 줄을 봅니다.**

각 지적에 대해 셋 중 하나로 판정합니다.

| 판정               | 뜻                                        |
| ------------------ | ----------------------------------------- |
| **맞다**     | 실제로 그 줄에 그 문제가 있다             |
| **틀렸다**   | 그런 코드가 없거나, 문제가 아니다         |
| **애매하다** | 문제이긴 하나 이 프로젝트 규모에선 과하다 |

### 2단계. 틀린 지적을 찾는다

| 흔한 잘못된 지적                         | 왜 틀렸나                                                                                  |
| ---------------------------------------- | ------------------------------------------------------------------------------------------ |
| "`Update()`에서 `GetComponent` 호출" | `Awake()` 에서 캐싱해 뒀는데 못 본 경우                                                  |
| "event 해제 누락"                        | `OnDisable` 에 있는데 놓친 경우, 또는 지역 함수로 스스로 해제하는 패턴을 이해 못 한 경우 |
| "존재하지 않는 줄 번호"                  | 줄 번호가 실제 파일과 어긋난 경우                                                          |
| "null 체크 필요"                         | `[RequireComponent]` 로 보장되는 참조인 경우                                             |

찾았으면 **근거를 들어 반박해 보세요.**

```
<지적 내용>은 틀린 것 같아. <파일:줄>을 보면 <실제 코드>야.
내가 잘못 이해한 건지, 지적이 틀린 건지 확인해줘.
```

> **AI가 순순히 물러서는지 보세요.**
> 근거 없이 "맞습니다, 죄송합니다"라고 하면 그것도 신뢰할 수 없다는 뜻입니다.

### 3단계. 우선순위 3개만 고친다

전부 고치지 마세요. **가장 심각한 3개만** 고릅니다.

```
확인해보니 <항목 A>, <항목 B>, <항목 C> 는 실제 문제가 맞아.
이 3개만 고쳐줘. 나머지는 두고.
각 수정마다 무엇을 왜 바꿨는지 한 줄로 설명해줘.
```

### 4단계. 다시 플레이 테스트한다

```
□ 웨이브가 정상 진행된다
□ HUD가 정상 갱신된다
□ 죽고 재시작이 된다
□ 콘솔에 에러가 없다
```

**리뷰 수정이 멀쩡한 코드를 망가뜨리는 일이 실제로 있습니다.**

### 에디터에서만 되는 코드란

| 흔한 것                           | 빌드에서 생기는 일                             |
| --------------------------------- | ---------------------------------------------- |

### 이 프로젝트는 창 모드로 빌드됩니다 ★

스타터에 이미 설정되어 있습니다. 따로 만질 것은 없지만, **왜 그런지는 알아두세요.**

```
Edit → Project Settings → Player → Resolution and Presentation

  Fullscreen Mode         Windowed
  Default Screen Width    1280
  Default Screen Height   720
  Resizable Window        체크
```

Unity의 기본값은 **전체 화면**입니다. 전체 화면 빌드는 **닫기 버튼이 없습니다.**
게임 안에 종료 수단이 없으면 `Alt+F4` 나 작업 관리자로만 빠져나올 수 있습니다.

창 모드면 제목 표시줄의 `X` 로 언제든 닫힙니다. 수업 중 Unity·Claude Code 와
화면을 오가기도 쉽습니다.

**그래도 `Esc` 종료는 넣습니다.** 중복이 아닙니다.
커서가 잠긴 상태에서는 마우스가 창 밖으로 나가지 않아 `X` 를 누르기 어렵습니다.
`Esc` 로 커서를 풀고 닫는 흐름이 자연스럽습니다.

에디터의 `Esc` 는 커서를 풀어주는 **에디터 전용 동작**이고, 빌드에는 그 동작이 없습니다.
그래서 3-1에서 `Esc` → `Application.Quit()` 을 직접 넣었습니다.

> **`Application.Quit()` 은 에디터에서 아무 일도 하지 않습니다.**
> 에디터에서 아무리 눌러 봐도 검증되지 않습니다. **빌드로만 확인할 수 있는 항목입니다.**
>
> 오늘 배운 것이 여기서도 반복됩니다 — 에러가 없다는 것이 정상이라는 뜻은 아닙니다.

## 빌드

```
File > Build Profiles → Windows 프로필 선택 → Build
```

출력 폴더는 **프로젝트 밖**에 만드세요. 안에 만들면 `.gitignore` 에 안 걸려 리포에 들어갑니다.

## 빌드 검증 — 에디터가 아니라 exe로

```
□ exe가 실행되고, 전체 화면이 아니라 창으로 뜬다
□ 창 오른쪽 위 X 로 닫힌다
□ 이동 / 사격 / 재장전이 된다
□ HUD가 보인다
□ 웨이브가 진행된다
□ 죽으면 게임오버 화면이 나온다
□ R로 재시작된다
□ Esc를 누르면 창이 닫힌다   ← 에디터에서는 확인 불가능한 항목
```

빌드는 프로젝트 폴더 밖에 만들었으므로 리포에 들어가지 않습니다.
첫 빌드는 1~2분, 두 번째부터는 10초 안팎입니다.
